## ✨ Overview

**AutoFilter Bot** turns a Telegram channel into a searchable file library. Users send a movie title, series name, document name, or keyword. The bot searches its MongoDB index, displays matching channel posts, and copies the selected post into the user's private chat.

### How it works

```text
User sends a keyword
        │
        ▼
AutoFilter Bot receives the query
        │
        ▼
MongoDB searches indexed channel posts
        │
        ▼
Bot displays matching files with page buttons
        │
        ▼
User selects a result
        │
        ▼
Bot copies the source-channel message to the user
```

## 🚀 Features

| Feature | Description |
|---|---|
| Keyword search | Search file names and captions |
| Case-insensitive matching | Uppercase and lowercase searches work |
| Multi-word search | Matches records containing all query words |
| Paginated results | Browse up to 10 results per page |
| Direct file delivery | Copies the selected channel message |
| Automatic indexing | Indexes supported new channel posts while the bot is running |
| MongoDB persistence | Keeps the search index across dyno restarts |
| Admin commands | Statistics, broadcast, indexing status and cache cleanup |
| Bot-token-only setup | No Pyrogram user session string is needed |

## 🧭 User experience

1. Open the bot and send `/start`.
2. Send a search term, for example `Avengers Endgame`.
3. Browse the matching results.
4. Tap the file you want.
5. The bot sends a copy of the selected channel post to your private chat.

## 🗂️ Supported media

The indexer is designed for common Telegram media types:

- Documents and archives
- Videos and video notes
- Audio and voice messages
- Photos
- Animations
- Stickers

Actual delivery depends on Telegram access, message availability, and source-channel restrictions.

## ⚙️ Requirements

- Python 3.11+
- Telegram bot token from [@BotFather](https://t.me/BotFather)
- Telegram API ID and API hash from [my.telegram.org](https://my.telegram.org)
- MongoDB database, such as MongoDB Atlas
- A Telegram channel where you have permission to manage the bot
- Heroku account if deploying to Heroku

## 🔐 Configuration

Create a `.env` file locally, or add these values as Heroku Config Vars.

| Variable | Required | Description |
|---|---:|---|
| `API_ID` | Yes | Telegram API application ID |
| `API_HASH` | Yes | Telegram API application hash |
| `BOT_TOKEN` | Yes | Token generated by BotFather |
| `ADMIN_ID` | Yes | Numeric Telegram user ID of the bot administrator |
| `DATABASE_URL` | Yes | MongoDB connection URI |
| `CHANNEL_ID` | Yes | Source channel ID, commonly beginning with `-100` |
| `BOT_NAME` | No | Bot display name; defaults to `Auto Filter Bot` |
| `RESULTS_PER_PAGE` | No | Number of results per page; defaults to 10 and is capped at 10 |
| `LOG_LEVEL` | No | Logging level; defaults to `INFO` |

> **No `SESSION_STRING` required.** This project runs using the Telegram bot account. Add the bot to the source channel as an administrator and grant it permission to access channel posts.

### Example `.env`

```env
API_ID=123456
API_HASH=your_api_hash
BOT_TOKEN=123456:your_bot_token
ADMIN_ID=123456789
DATABASE_URL=mongodb+srv://username:password@cluster.example.mongodb.net/?retryWrites=true&w=majority
CHANNEL_ID=-1001234567890
BOT_NAME=Auto Filter Bot
RESULTS_PER_PAGE=10
LOG_LEVEL=INFO
```

Never commit `.env`, credentials, or database passwords to Git.

## ☁️ Deploy to Heroku

This repository uses a worker process for the continuously running Telegram bot.

### 1. Create the Heroku app

Create an app in the Heroku Dashboard, or use the CLI:

```bash
heroku login
heroku create YOUR-APP-NAME
```

### 2. Add Config Vars

In **Heroku Dashboard → Your App → Settings → Config Vars**, add all required variables from the configuration table. Do not add `SESSION_STRING`.

### 3. Connect and deploy

If the repository is already connected to your local Git checkout:

```bash
heroku git:remote -a YOUR-APP-NAME
git add .
git commit -m "Configure AutoFilter Bot"
git push heroku main
```

If your deployment branch is `master`, push that branch instead:

```bash
git push heroku master
```

### 4. Enable the worker

```bash
heroku ps:scale worker=1 -a YOUR-APP-NAME
```

### 5. View logs

```bash
heroku logs --tail -a YOUR-APP-NAME
```

Use one worker instance for a single bot token unless you have intentionally configured a multi-instance architecture.

## 🛡️ Telegram channel setup

1. Open your source Telegram channel.
2. Add your bot as an administrator.
3. Grant the permissions needed for the bot to access channel posts.
4. Set the correct `CHANNEL_ID` in your environment.
5. Post a new test file after the bot is running.
6. Search for that file name in the bot.

The bot must be able to access the original channel message to copy it to a user. Protected content, deleted messages, or Telegram restrictions may prevent copying.

## 🗃️ Important: Existing channel files vs. new uploads

This is a **bot-token-only** implementation.

- **New channel posts:** The bot can index supported new posts that it receives while running, provided it has the required channel access.
- **Older channel history:** The Telegram Bot API does not provide a general method for a bot to enumerate every old message in a channel. Therefore, simply adding the bot does not automatically populate MongoDB with all historical files.
- **Existing library migration:** If you need old files searchable, use a separate authorized import/reposting workflow to populate the MongoDB index. Do not assume `/index` can scan the entire channel history in bot-only mode.

## 🤖 Bot commands

### User commands

| Command / action | Description |
|---|---|
| `/start` | Start the bot and show instructions |
| `/help` | Show usage help |
| Send any keyword | Search indexed files |
| Tap a result | Receive a copy of the selected message |
| Next / Previous | Navigate search result pages |

### Admin commands

| Command | Description |
|---|---|
| `/stats` | Show registered users and indexed file counts |
| `/users` | Show registered user count |
| `/index` | Explain current indexing mode |
| `/reindex` | Explain historical indexing limitation in bot-only mode |
| `/clearcache` | Clear temporary search sessions |
| Reply to a message with `/broadcast` | Broadcast the replied-to message to registered users |

Admin commands are restricted to the configured `ADMIN_ID`.

## 🩺 Troubleshooting

| Problem | What to check |
|---|---|
| Bot does not start | Check `API_ID`, `API_HASH`, `BOT_TOKEN`, and Heroku logs |
| MongoDB connection fails | Verify `DATABASE_URL`, Atlas network access, and database user permissions |
| New channel posts are not indexed | Confirm the bot is an administrator, `CHANNEL_ID` is correct, and the worker is running |
| Search returns no results | Confirm the file was indexed after the bot started; try a shorter keyword |
| File cannot be delivered | Check that the source message still exists and is accessible, and that content protection does not block copying |
| Old channel files are missing | They must be imported through a separate historical-data workflow |

## 🔒 Security and responsible use

- Keep bot tokens, API credentials, and database URIs private.
- Never commit `.env` or session credentials.
- Restrict admin access to your own Telegram user ID.
- Give database users only the permissions they need.
- Only index and distribute files that you own or are authorized to share.
- Respect copyright, privacy, and Telegram's terms and content restrictions.
